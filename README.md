# claude-skill-pyright-envs

Generate a `pyrightconfig.json` with one `executionEnvironment` per package, so that Go
to Definition in a monorepo resolves each file against its own import paths instead of
another package's vendored copy of the same module.

A [Claude Code](https://claude.com/claude-code) skill (see `SKILL.md`) wrapped around a
small, dependency-free CLI (`scripts/gen_pyright_envs.py`) that also works perfectly well
on its own, from a terminal or a CI job.

## The problem, illustrated

Two packages, `alpha` and `beta`, each vendor their own copy of `sharedlib`:

```
packages/
  alpha/
    src/alpha_app/__init__.py     # from sharedlib import VERSION
    vendor/sharedlib/__init__.py  # VERSION = "alpha-copy"
  beta/
    src/beta_app/__init__.py      # from sharedlib import VERSION
    vendor/sharedlib/__init__.py  # VERSION = "beta-copy"
```

**Before**: a single flat Pyright/Pylance index cannot tell the two `sharedlib` copies
apart. Ctrl+click on `sharedlib.VERSION` from `alpha_app` may resolve to `beta`'s copy —
silently. Autocomplete and Go to Definition both point at the wrong file, and imports
still appear to work.

**After**: this tool generates one `executionEnvironment` per package, each with its own
`extraPaths`:

```jsonc
// Generated by gen_pyright_envs.py from pyright-envs.layout.toml. Do not edit by hand.
{
  "include": ["packages"],
  "exclude": ["**/node_modules", "**/.venv", "**/__pycache__", "**/dist", "**/build"],
  "pythonVersion": "3.11",
  "pythonPlatform": "All",
  "typeCheckingMode": "off",
  "executionEnvironments": [
    { "root": "packages/alpha", "extraPaths": ["packages/alpha/src", "packages/alpha/vendor"] },
    { "root": "packages/beta", "extraPaths": ["packages/beta/src", "packages/beta/vendor"] },
    { "root": "packages" }
  ]
}
```

Now a file under `packages/alpha` only ever resolves `sharedlib` against
`packages/alpha/vendor`, and a file under `packages/beta` only ever resolves it against
`packages/beta/vendor`.

Excluding vendored trees from the workspace scan (via the top-level `exclude` list) also
keeps Pylance's indexed file count down in a large monorepo, without breaking resolution:
Pyright still analyzes an excluded file when it is imported by a file that is not
excluded, per Pyright's own documented behavior — `extraPaths` is what makes that lookup
succeed.

## Installation

Requires Python 3.11 or newer on `PATH`. There are no runtime dependencies — the tool is
stdlib-only.

```bash
git clone https://github.com/lucas-lima-s/claude-skill-pyright-envs.git
cd claude-skill-pyright-envs
uv sync --dev   # or: pip install -r requirements-dev.txt
```

## Usage

Create a `pyright-envs.toml` at your workspace root (see
[Configuration](#configuration) below, or copy `pyright-envs.example.toml`), then run:

```bash
python scripts/gen_pyright_envs.py
```

This writes `pyrightconfig.json` next to the config file (or wherever `out` points to).
Useful variations:

```bash
python scripts/gen_pyright_envs.py --config path/to/pyright-envs.toml
python scripts/gen_pyright_envs.py --root /path/to/workspace
python scripts/gen_pyright_envs.py --out -              # print to stdout
python scripts/gen_pyright_envs.py --check              # exit 1 if the file is stale (CI mode)
python scripts/gen_pyright_envs.py --quiet              # suppress the stderr summary
```

After regenerating, reload the editor window or run "Python: Restart Language Server" so
Pyright/Pylance picks up the new `executionEnvironments`.

`pyrightconfig.json` is small enough, and useful enough for every teammate, that
committing it is the recommended default. If a project prefers not to commit generated
files, add `pyrightconfig.json` to `.git/info/exclude` and run `--check` in CI instead, so
drift between the config and the generator's output is still caught.

## Configuration

`pyright-envs.toml`, parsed with `tomllib` — unknown keys are a hard error naming the
key, so a typo never silently produces the wrong config.

| Key | Default | Meaning |
|---|---|---|
| `root` | `"."` | Workspace root discovery paths are resolved against. |
| `out` | `"pyrightconfig.json"` | Output path, or overridden by `--out`. |
| `python_version` | `"3.11"` | Written as `pythonVersion` in the generated config. |
| `python_platform` | `"All"` | Written as `pythonPlatform`. |
| `type_checking_mode` | `"off"` | Written as `typeCheckingMode`. This tool's job is navigation; turning on type checking is a separate decision left to the project. |
| `include` | `["."]` | Written as the top-level `include`; `include[0]` is also the catch-all environment's root. |
| `exclude` | see below | Written as the top-level `exclude`. |
| `shared_roots` | `[]` | Paths appended to every package's `extraPaths` if they exist; a missing one is reported once on stderr and dropped. |
| `append_catch_all` | `true` | Whether to append `{"root": include[0]}` as a final, catch-all environment. |
| `discovery.provider` | — | One of `"layout"`, `"manifest"`, `"xml"`. |

Default `exclude`: `**/node_modules`, `**/.venv`, `**/__pycache__`, `**/dist`,
`**/build`, `**/.mypy_cache`, `**/.ruff_cache`, `**/.pytest_cache`.

### `discovery.layout`

Convention-based discovery via glob.

| Key | Default | Meaning |
|---|---|---|
| `packages` | `"packages/*"` | Glob (relative to `root`) yielding one directory per package. |
| `source_dirs` | `["src"]` | Candidate source directory names under each package. |
| `vendor_dirs` | `["vendor"]` | Candidate vendored-module directory names. |
| `test_dirs` | `["tests", "test"]` | Candidate test directory names. |
| `require_python` | `true` | Skip a matched directory if no `.py` file exists anywhere under it. |
| `skip_prefixes` | `["_", "."]` | Directory names starting with any of these are skipped. |

### `discovery.manifest`

Fully explicit, per-package declaration — no scanning:

```toml
[discovery.manifest.packages.alpha]
root = "packages/alpha"
extra_paths = ["packages/alpha/src", "packages/alpha/vendor", "shared-kernel/src"]
```

Paths are kept verbatim, in the order given; a path that does not exist on disk is
dropped.

### `discovery.xml`

Generic, selector-driven discovery from launcher-style XML files.

| Key | Meaning |
|---|---|
| `files` | Glob (relative to `root`) for the XML files to scan. |
| `path_list_selector` | An `ElementTree`-compatible path selecting the ordered list of path strings, e.g. `.//group[@name='Process']/key[@name='Arguments']/array/string`. |
| `skip_first_if_matches` | Optional regex; if the first extracted string matches, it is dropped (for a leading script-name argument). |
| `root_pattern` | Regex with a named group `name`, matched against each raw entry to find the one that identifies the package. |
| `root_template` | Default `"packages/{name}"`; formatted with the matched `name` to produce the package's root. |
| `path_prefix_strip` | Literal prefix stripped from the start of a plain path entry to make it root-relative. |
| `suffix_map` | Table of `"<suffix>" = "<template>"`; an entry ending in a configured suffix is expanded via `template.format(name=...)` instead of being prefix-stripped. |

## Sample monorepo

`examples/sample-monorepo/` is a small, self-contained fixture exercising all three
providers: `alpha` and `beta` vendor different copies of the same module, `gamma` uses a
shared root instead of vendoring, `delta` is discoverable only through
`deploy/delta/launcher.xml`, and `frontend/` is JS-only and must produce no environment.
`examples/sample-monorepo/expected/` holds the golden output for each provider; run

```bash
python scripts/gen_pyright_envs.py --config examples/sample-monorepo/pyright-envs.layout.toml --out - 
```

from the repository root to see it generated live.
